# Full internal case review

Date: 24 October 2026. Reviewer: Codex AI assistant, using the judgment delegated by the user. This completes internal review of all 24 cases, including the remaining 21. It is post hoc, AI-assisted review by the same project workflow, not independent human domain validation. The earlier H08/H12/H17 review remains preserved.

## Decision and scope

Retain all recorded study results. Every evaluated fixture has an internally consistent expected recovery under the documented interpretation. The review does not establish that every input allowed by a loose reading of a specification is handled correctly. Four separate boundary probes expose limitations in H04, H12, H23 and H24. H19 also needs clearer wording about reset records. None of those probes is a sealed case, model attempt or replacement observation.

No additional GPU run is needed to report the existing fixture results and these limitations. A future benchmark extension that resolves ambiguities or adds the uncovered inputs must have a new specification and version. The current original, corrected H08, v3 model comparison and post hoc scope-adaptation diagnostic remain separate. The new review is an additional internal audit, not a fifth model study.

## What was actually checked

Read all 24 business specifications, source schemas, SQL reference strategies, Python oracles, damaged states and continuation states. Constructed explicit expected rows using case-specific arithmetic and policy decisions, without calling the oracle or SQL to construct those expectations. Compared initial and continuation expectations at seeds 0, 7 and 19: 144 projection comparisons across 72 case/seed combinations. Also checked 72 healthy-state projections and reran the 24-case admission suite, which checks both reference strategies and seven incorrect controls per case over the three variants.

All recorded-fixture checks passed. These are additional consistency checks, not independent observations, model trials or proof of general correctness. The [machine-readable review](case-review-v2-checks.json) includes every expected row, admission result and boundary probe. The [standalone CPU script](../tools/review_all_cases_v2.py) reproduces them from the unchanged v3 source snapshot. The original harness bug is still disclosed; using the corrected source for this semantic audit does not retrospectively repair the original study.

All cases assume trusted, complete source evidence, a static offline copy and rebuildable projections. An accepted fixture is not an endorsement of the same recovery operation in a live production system.

## Separate boundary probes and impact

1. **H04 equal valid sequence:** add a second valid current-lease completion at sequence 1 with value 999. On the tested runtime, the Python oracle selects 999 while reference SQL selects 40. Neither selection is an established business rule. All evaluated fixtures are free of these ties.
2. **H12 equal accepted sequence:** add a second accepted current-generation sequence-1 value of 999. The oracle selects a row by stable list order; the SQL reference fails a cache primary-key constraint. All evaluated fixtures are tie-free. The frozen specification did not explicitly state a uniqueness requirement.
3. **H23 empty stream:** add a stream with no partition rows. SQL emits a NULL complete-through marker and the oracle emits zero. The phrase 'slots ... starting at one' does not settle a useful empty-stream policy. Existing evaluated streams all have partitions; do not claim empty-stream support.
4. **H24 parent erasure:** give a surviving child a currently valid parent, then erase the parent's subject. With only the parent's ID in work, the patch leaves a stale child pointer. Including the child's ID produces the expected detached row. This dependency expansion is not explicit in H24's frozen prompt. The evaluated continuation already produces correct outputs with its supplied work list.

These probes are not new model failures or additions to the benchmark denominator. They reveal untested assumptions or implementation boundaries. The reference patch is validated for the recorded fixture transitions; it is not proven correct for every conceivable input. Future versions should specify ties, empty-stream output and affected-ID expansion before adding new cases. Do not retrofit those rules into the historical prompts.

## Grader and claim judgment

The graders check final snapshots. A delete-and-rebuild strategy may pass preservation because it restores the same permitted rows. Stable state does not mean zero repeated writes, transactional safety under concurrency or absence of downstream effects. The future-patch component validates supplied SQL; it is not a model-generated code result. These distinctions stay in the paper.

All cases share the empty-work pattern and allow full reconstruction. The existing post hoc filter-removal diagnostic still achieves 24/24. This review does not strengthen the novelty claim, establish independent value of every metric, or make the six families independent real-world systems. It supports a narrow, reproducible evaluation on the explicit fixtures.
