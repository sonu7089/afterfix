## Business rules

The role graph is a finite DAG. A user receives enabled grants on every directly assigned role and every transitively inherited parent. An explicit (user,resource) deny overrides every path. Disabled grants never authorize access; multiple paths produce one access row. access_counts includes users with zero access. The fixed patch refreshes only users listed in work; the change-feed expands affected users before invoking it. Preserve the legitimate explicit deny and grants through independent inheritance paths. All evidence tables including work are immutable. Listed projections are rebuildable. Recover all historical damage, preserve unrelated correct records, and leave an already healthy snapshot unchanged. Recovery and subsequent patch processing must be repeatable.

## Evidence

- A stale effective-access cache retained a denied export and omitted grants reachable through a parent role.
- memberships + role_edges + grants + denies -> effective_access -> access_counts; work -> effective_access
- The diamond inheritance has two paths to viewer; the later explicit deny applies only to one user.

Immutable tables: users, memberships, role_edges, grants, denies, work.
Writable projections: effective_access, access_counts.
Full rebuilding is allowed. No append-only requirement is present.

## Supplied application patch

```sql
DELETE FROM effective_access WHERE user IN (SELECT entity FROM work); INSERT INTO effective_access WITH RECURSIVE reach(user,role) AS (SELECT user,role FROM memberships UNION
SELECT r.user,e.parent FROM reach r JOIN role_edges e ON e.child=r.role) SELECT DISTINCT r.user,g.resource FROM reach r JOIN grants g ON g.role=r.role WHERE g.enabled=1 AND NOT EXISTS(SELECT 1 FROM denies d WHERE d.user=r.user AND d.resource=g.resource) AND r.user IN (SELECT entity FROM work); DELETE FROM access_counts; INSERT INTO access_counts SELECT u.id,(SELECT COUNT(*) FROM effective_access a WHERE a.user=u.id) FROM users u;
```
