# H21: ClearBatch: a stale approval released an incomplete revised batch

**Review status: internal AI review complete; evaluated fixtures accepted with documented scope.**

This is not independent human validation. The historical specification below is unchanged.

Review qualification: See the full review for business-policy assumptions and production limits.

This card shows seed 0. The source generator also supplies variants 7 and 19.

## Business rules

Every batch has one releases row. An active hold means held regardless of approvals. Otherwise release only when the number of items at the batch current revision equals expected_count and the highest-seq review at that same revision is allow; missing review or any other condition means blocked. item_count counts only current-revision items. Expected counts are positive; older items and reviews remain audit evidence, not current authorization. seq is comparable only within a batch revision. The patch refreshes batch IDs in work after new evidence arrives. Recovering history must retain later holds and denied re-reviews. All evidence tables including work are immutable. Listed projections are rebuildable. Recover all historical damage, preserve unrelated correct records, and leave an already healthy snapshot unchanged. Recovery and subsequent patch processing must be repeatable.

## Evidence

- An approval join ignored revision and admitted a revised batch using its retired approval; arrival totals hid an incomplete current revision.
- batches + items + reviews + holds -> releases; work -> releases
- An independently imposed hold overrides an approval. A complete healthy released batch is an unrelated control.

Immutable tables: batches, items, reviews, holds, work.
Writable projections: releases.
Full rebuilding is allowed. No append-only requirement is present.

## Schema and column order

```sql
CREATE TABLE batches(id TEXT PRIMARY KEY,revision INTEGER,expected_count INTEGER);
CREATE TABLE items(batch TEXT,revision INTEGER,id TEXT,payload TEXT,PRIMARY KEY(batch,revision,id));
CREATE TABLE reviews(batch TEXT,revision INTEGER,seq INTEGER,decision TEXT,PRIMARY KEY(batch,revision,seq));
CREATE TABLE holds(batch TEXT PRIMARY KEY,active INTEGER);
CREATE TABLE work(entity TEXT PRIMARY KEY);
CREATE TABLE releases(batch TEXT PRIMARY KEY,state TEXT,item_count INTEGER);
```

## Supplied application patch

```sql
DELETE FROM releases WHERE batch IN (SELECT entity FROM work); INSERT INTO releases SELECT b.id,CASE WHEN EXISTS(SELECT 1 FROM holds h WHERE h.batch=b.id AND h.active=1) THEN 'held'
WHEN (SELECT COUNT(*) FROM items i WHERE i.batch=b.id AND i.revision=b.revision)=b.expected_count
AND (SELECT decision FROM reviews r WHERE r.batch=b.id AND r.revision=b.revision ORDER BY seq DESC LIMIT 1)='allow' THEN 'released' ELSE 'blocked' END,
(SELECT COUNT(*) FROM items i WHERE i.batch=b.id AND i.revision=b.revision) FROM batches b WHERE b.id IN (SELECT entity FROM work);
```
