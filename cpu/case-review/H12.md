# H12: CacheForge: a reused object key inherited its deleted incarnation cache

**Review status: internal AI review complete; evaluated fixtures accepted with documented scope.**

This is not independent human validation. The historical specification below is unchanged.

Review qualification: Conflicting accepted materializations with the same sequence have no specified tie-break; none occur in evaluated fixtures.

This card shows seed 0. The source generator also supplies variants 7 and 19.

## Business rules

Cache only active objects with an accepted materialization for their current generation. Choose its highest seq within that generation. No row for deleted or cold objects. Sequence numbers from an old incarnation cannot be compared against the current generation. Rejected materializations have no effect. The fixed patch refreshes only key IDs in work for cache, then refreshes any dependent summaries. Historical IDs are absent from work. All evidence tables including work are immutable. Listed projections are rebuildable. Recover all historical damage, preserve unrelated correct records, and leave an already healthy snapshot unchanged. Recovery and subsequent patch processing must be repeatable.

## Evidence

- A key-only upsert revived generation 2 after the key was recreated at generation 3.
- objects + materializations -> cache; work -> cache

Immutable tables: objects, materializations, work.
Writable projections: cache.
Full rebuilding is allowed. No append-only requirement is present.

## Schema and column order

```sql
CREATE TABLE objects(key TEXT PRIMARY KEY,generation INTEGER,active INTEGER);
CREATE TABLE materializations(id TEXT PRIMARY KEY,key TEXT,generation INTEGER,seq INTEGER,value INTEGER,accepted INTEGER);
CREATE TABLE cache(key TEXT PRIMARY KEY,generation INTEGER,value INTEGER,seq INTEGER);
```

## Supplied application patch

```sql
DELETE FROM cache WHERE key IN (SELECT entity FROM work); INSERT INTO cache SELECT * FROM (SELECT o.key,o.generation,m.value,m.seq FROM objects o JOIN materializations m ON m.key=o.key AND m.generation=o.generation WHERE o.active=1 AND m.accepted=1 AND NOT EXISTS(SELECT 1 FROM materializations x WHERE x.key=m.key AND x.generation=m.generation AND x.accepted=1 AND x.seq>m.seq)) WHERE key IN (SELECT entity FROM work);
```
