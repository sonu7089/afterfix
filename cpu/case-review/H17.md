# H17: GaugeLine: a late meter correction was added instead of replacing the prior reading

**Review status: internal AI review complete; evaluated fixtures accepted with documented scope.**

This is not independent human validation. The historical specification below is unchanged.

Review qualification: See the full review for business-policy assumptions and production limits.

This card shows seed 0. The source generator also supplies variants 7 and 19.

## Business rules

For each meter start at opening and process commands in increasing authoritative seq, not arrival order. SET replaces the whole current value; ADD adds a signed amount. seq is positive and unique within a meter. readings has one row per meter, value after all commands, and last_seq equal to max seq or zero for no commands. An older correction may arrive after later commands; later SET and ADD effects must still survive in authoritative order. The patch refreshes only changed meter IDs in work; all earlier readings remain untouched unless explicitly recovered. All evidence tables including work are immutable. Listed projections are rebuildable. Recover all historical damage, preserve unrelated correct records, and leave an already healthy snapshot unchanged. Recovery and subsequent patch processing must be repeatable.

## Evidence

- The broken materializer treated SET as an additive delta and sorted correction arrivals rather than authoritative sequences.
- meters + commands -> readings; work -> readings
- The late SET at sequence 2 precedes the later SET at sequence 4, regardless of arrival time. An idle meter is a zero-event control.

Immutable tables: meters, commands, work.
Writable projections: readings.
Full rebuilding is allowed. No append-only requirement is present.

## Schema and column order

```sql
CREATE TABLE meters(id TEXT PRIMARY KEY,opening INTEGER);
CREATE TABLE commands(id TEXT PRIMARY KEY,meter TEXT,seq INTEGER,kind TEXT,amount INTEGER,arrival INTEGER,UNIQUE(meter,seq));
CREATE TABLE work(entity TEXT PRIMARY KEY);
CREATE TABLE readings(meter TEXT PRIMARY KEY,value INTEGER,last_seq INTEGER);
```

## Supplied application patch

```sql
DELETE FROM readings WHERE meter IN (SELECT entity FROM work); INSERT INTO readings SELECT m.id,COALESCE((SELECT amount FROM commands c WHERE c.meter=m.id AND c.kind='SET' ORDER BY seq DESC LIMIT 1),m.opening)+
COALESCE((SELECT SUM(amount) FROM commands c WHERE c.meter=m.id AND c.kind='ADD' AND c.seq>COALESCE((SELECT MAX(seq) FROM commands s WHERE s.meter=m.id AND s.kind='SET'),0)),0),
COALESCE((SELECT MAX(seq) FROM commands c WHERE c.meter=m.id),0) FROM meters m WHERE m.id IN (SELECT entity FROM work);
```
