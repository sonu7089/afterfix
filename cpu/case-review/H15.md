**Review status: internal AI review complete; evaluated fixtures accepted with documented scope.**

## Business rules

Active direct assignments retain their origin team and ignore routing. Active inherited assignments contribute only accepted routing targets, never their old origin. A split can route one assignment to multiple targets; a merge can create multiple independent sources for one membership. Store one (user,team) row with the number of contributing assignment IDs. Inactive assignments and rejected routes do not contribute. The fixed patch refreshes only user IDs in work for membership, then refreshes any dependent summaries. Historical IDs are absent from work. All evidence tables including work are immutable. Listed projections are rebuildable. Recover all historical damage, preserve unrelated correct records, and leave an already healthy snapshot unchanged. Recovery and subsequent patch processing must be repeatable.

## Evidence

- A group split applied routing to direct assignments and retained retired inherited origins.
- assignments + routing -> membership; work -> membership

Immutable tables: assignments, routing, work.
Writable projections: membership.
Full rebuilding is allowed. No append-only requirement is present.

## Schema and column order

```sql
CREATE TABLE assignments(id TEXT PRIMARY KEY,user TEXT,origin TEXT,kind TEXT,active INTEGER);
CREATE TABLE routing(assignment TEXT,target TEXT,accepted INTEGER,PRIMARY KEY(assignment,target));
```

## Supplied application patch

```sql
DELETE FROM membership WHERE user IN (SELECT entity FROM work); INSERT INTO membership SELECT * FROM (SELECT user,team,COUNT(*) FROM (SELECT user,origin AS team FROM assignments WHERE kind='direct' AND active=1 UNION ALL SELECT a.user,r.target FROM assignments a JOIN routing r ON r.assignment=a.id WHERE a.kind='inherited' AND a.active=1 AND r.accepted=1) GROUP BY user,team) WHERE user IN (SELECT entity FROM work);
```
