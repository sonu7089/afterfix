# H09: LakeSpan: an index mixed obsolete and unpublished snapshot files

**Review status: internal AI review complete; evaluated fixtures accepted with documented scope.**

This is not independent human validation. The historical specification below is unchanged.

Review qualification: See the full review for business-policy assumptions and production limits.

This card shows seed 0. The source generator also supplies variants 7 and 19.

## Business rules

heads identifies the authoritative published snapshot for each dataset; heads always points to a committed snapshot belonging to that dataset. Only that snapshot membership determines active_files. Older committed snapshots and staged unpublished snapshots contribute nothing. The same file may belong to different datasets; distinct files with equal row counts must both count. dataset_totals includes every head, including zero-file snapshots. The patch refreshes only dataset IDs in work after a publication, then recomputes dataset_totals. All evidence tables including work are immutable. Listed projections are rebuildable. Recover all historical damage, preserve unrelated correct records, and leave an already healthy snapshot unchanged. Recovery and subsequent patch processing must be repeatable.

## Evidence

- A maintenance index unioned every snapshot membership and accidentally included a staging manifest.
- heads + snapshots + members + files -> active_files -> dataset_totals; work -> active_files
- A second dataset legitimately uses the shared file; physical-file deduplication across datasets would lose its rows.

Immutable tables: snapshots, heads, members, files, work.
Writable projections: active_files, dataset_totals.
Full rebuilding is allowed. No append-only requirement is present.

## Schema and column order

```sql
CREATE TABLE snapshots(id TEXT PRIMARY KEY,dataset TEXT,status TEXT);
CREATE TABLE heads(dataset TEXT PRIMARY KEY,snapshot TEXT);
CREATE TABLE members(snapshot TEXT,file TEXT,PRIMARY KEY(snapshot,file));
CREATE TABLE files(id TEXT PRIMARY KEY,rows INTEGER);
CREATE TABLE work(entity TEXT PRIMARY KEY);
CREATE TABLE active_files(dataset TEXT,file TEXT,rows INTEGER,PRIMARY KEY(dataset,file));
CREATE TABLE dataset_totals(dataset TEXT PRIMARY KEY,rows INTEGER);
```

## Supplied application patch

```sql
DELETE FROM active_files WHERE dataset IN (SELECT entity FROM work); INSERT INTO active_files SELECT h.dataset,f.id,f.rows FROM heads h JOIN snapshots s ON s.id=h.snapshot AND s.dataset=h.dataset AND s.status='committed' JOIN members m ON m.snapshot=s.id JOIN files f ON f.id=m.file WHERE h.dataset IN (SELECT entity FROM work); DELETE FROM dataset_totals; INSERT INTO dataset_totals SELECT h.dataset,COALESCE((SELECT SUM(a.rows) FROM active_files a WHERE a.dataset=h.dataset),0) FROM heads h;
```
