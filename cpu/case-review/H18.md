# H18: AmendStay: a cancellation for an old version removed a reinstated reservation

**Review status: internal AI review complete; evaluated fixtures accepted with documented scope.**

## Business rules

Process actions in seq order. activate installs its version and quantity, superseding earlier versions. cancel and reinstate affect only the currently active version; stale-version actions do nothing. Reinstate restores that version quantity. All versions are activated once in increasing version order, every reservation is activated, and later cancellation/reinstatement references existing versions. Store current version even when canceled (qty zero). The fixed patch refreshes only reservation IDs in work for allocation, then refreshes any dependent summaries. Historical IDs are absent from work. All evidence tables including work are immutable. Listed projections are rebuildable. Recover all historical damage, preserve unrelated correct records, and leave an already healthy snapshot unchanged. Recovery and subsequent patch processing must be repeatable.

## Evidence

- A delayed cancellation for version 1 was applied after version 2 had been reinstated.
- reservations + versions + actions -> allocation; work -> allocation

Immutable tables: reservations, versions, actions, work.
Writable projections: allocation.
Full rebuilding is allowed. No append-only requirement is present.

## Supplied application patch

```sql
DELETE FROM allocation WHERE reservation IN (SELECT entity FROM work); INSERT INTO allocation SELECT * FROM (WITH current AS (SELECT r.id,(SELECT version FROM actions a WHERE a.reservation=r.id AND a.kind='activate' ORDER BY seq DESC LIMIT 1) AS v FROM reservations r) SELECT c.id AS reservation,c.v,CASE WHEN (SELECT kind FROM actions a WHERE a.reservation=c.id AND a.version=c.v ORDER BY seq DESC LIMIT 1)='cancel' THEN 0 ELSE v.qty END FROM current c JOIN versions v ON v.reservation=c.id AND v.version=c.v) WHERE reservation IN (SELECT entity FROM work);
```
