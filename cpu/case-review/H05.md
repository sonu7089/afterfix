# H05: PackForge: one component of a committed kit reservation disappeared

**Review status: internal AI review complete; evaluated fixtures accepted with documented scope.**

This is not independent human validation. The historical specification below is unchanged.

Review qualification: See the full review for business-policy assumptions and production limits.

This card shows seed 0. The source generator also supplies variants 7 and 19.

## Business rules

A committed bundle reserves exactly the units of every component listed in parts. A released bundle reserves nothing. allocations has one row per committed (bundle,sku), not a partial kit or a merged SKU total. available equals inventory.total minus all allocations per SKU. All recorded commitments fit capacity. Releases are legitimate later activity and must not be reversed. The fixed patch updates allocations only for changed bundle IDs in work, then refreshes global available quantities. All evidence tables including work are immutable. Listed projections are rebuildable. Recover all historical damage, preserve unrelated correct records, and leave an already healthy snapshot unchanged. Recovery and subsequent patch processing must be repeatable.

## Evidence

- A per-component retry left a half-reserved kit; another kit was legitimately released later.
- bundles + parts -> allocations; inventory + allocations -> available; work -> allocations
- Two committed bundles share a component; repairing only its aggregate does not restore each bundle obligation.

Immutable tables: inventory, bundles, parts, work.
Writable projections: allocations, available.
Full rebuilding is allowed. No append-only requirement is present.

## Schema and column order

```sql
CREATE TABLE inventory(sku TEXT PRIMARY KEY,total INTEGER);
CREATE TABLE bundles(id TEXT PRIMARY KEY,status TEXT);
CREATE TABLE parts(bundle TEXT,sku TEXT,units INTEGER,PRIMARY KEY(bundle,sku));
CREATE TABLE work(entity TEXT PRIMARY KEY);
CREATE TABLE allocations(bundle TEXT,sku TEXT,qty INTEGER,PRIMARY KEY(bundle,sku));
CREATE TABLE available(sku TEXT PRIMARY KEY,qty INTEGER);
```

## Supplied application patch

```sql
DELETE FROM allocations WHERE bundle IN (SELECT entity FROM work); INSERT INTO allocations SELECT p.bundle,p.sku,p.units FROM parts p JOIN bundles b ON b.id=p.bundle WHERE b.status='committed' AND b.id IN (SELECT entity FROM work); DELETE FROM available; INSERT INTO available SELECT i.sku,i.total-COALESCE((SELECT SUM(a.qty) FROM allocations a WHERE a.sku=i.sku),0) FROM inventory i;
```
